DIFFERENTIATION

三大前沿机制

M1 / TRACE → SKILL

轨迹蒸馏回路

成功、失败和转人工轨迹进入 Evidence Pack，经敏感信息与许可证扫描后形成 SkillCandidate。

  • 原任务保真测试
  • 相似任务泛化测试
  • 不应触发的反例测试
  • JudgeCalibrator + 人工审核 + 灰度发布
  • 第二任务复用与回滚
M2 / INDEPENDENT VERIFICATION

对抗验证门

Builder 与 Verifier 使用不同上下文视图，以可执行证据而非文本争论决定是否通过。

  • Verifier 只读产物、规范和独立证据
  • 公开测试 + 隐藏回归 + 变异测试
  • 结构化 Failure Signature
  • 同一签名最多三次，之后转人工
  • Executor 无权修改验证标准
M3 / RESILIENT EXECUTION

断点续跑韧性层

为低风险夜间任务提供可恢复执行，控制重复副作用和悬空工具调用。

  • checkpoint、state_version、幂等键
  • query-before-create、lease、fencing token
  • watchdog、session/fork/recap
  • 人工恢复阶梯与悬空 tool_call 检查
  • kill、协议破损、命令挂死、网络分区演练

研究启发：Trace2Skill、MIND-Skill、ACE、Agentless、SetupBench、SWE-EVO。正式提交材料需要补齐标题、链接、版本、证据等级和借鉴边界。

AGENT ORGANIZATION

8 个 Agent：状态所有权、边界和产物

Agent状态所有权核心产物关键边界验收指标实现状态
IntakeRECEIVED / FUSEDIssueCluster不判根因，不改仓库聚类准确率、重复任务减少率Identity + workflow
TriageTRIAGEDRiskAssessment不授权超策略动作风险分级准确率、错误自动执行率Identity + artifact
EnvBootstrapBOOTSTRAPPEDEnvironmentSnapshot只在隔离环境准备环境准备成功率、基线复现率Fixture snapshot
RepoAnalystLOCATEDRootCauseHypotheses证据不足不得出 patch根因 Top-k、最终命中率两假设 + fan-in
PlanPLANNED / AWAITING_APPROVALChangePlan不直接执行修改计划一次批准率三计划 + 审批范围
ExecutorPATCHEDPatchBundle不扩大批准范围越权拦截率、diff 合规率fixture-local + adapter
VerifierVERIFYING / RELEASE_READYVerificationReport不修代码，只验证阻断隐藏回归判定准确率失败签名 + 重试
PostmortemPOSTMORTEM / SKILL_DISTILLINGSkillCandidate不绕过审核发布 SkillSkill 晋升通过率、复用成功率Candidate artifact
8 个 Agent 不代表每个任务固定调用 8 个。正式 AgentTeams 调度需按身份许可、状态匹配、风险级、Provider 健康、版本兼容、审批要求、预算和禁用版本动态激活。

STATE AUTHORITY

状态机与异常转移

RECEIVED→FUSED→TRIAGED→BOOTSTRAPPED→LOCATED→PLANNED→AWAITING_APPROVAL→PATCHED→VERIFYING→RELEASE_READY→POSTMORTEM→SKILL_DISTILLING→CLOSED

证据不足

RepoAnalyst → NEEDS_HUMAN

验证失败

VERIFYING → PATCHED

执行中断

执行态 → RECOVERING

checkpoint、state_version 和人工恢复阶梯共同决定续跑位置。

EVALUATION

指标、数据集和消融

主指标

端到端完成率、根因 Top-k、patch 通过率、隐藏回归通过率、Evidence 完整率、正确转人工率、越权拦截率、恢复成功率、Skill 独立任务复用率、Provider 切换一致性、单任务时间 / token / 调用 / 成本。

评测集

开源长程任务集、脱敏真实 issue、原因已知模拟回归集、升级/工具失败/环境残缺/越权/提示注入异常集，以及成功、失败、转人工和反例任务。

消融实验

完整 8 Agent vs 去 EnvBootstrap；Executor 自验证 vs 独立 Verifier；有无 IncidentMemory、ResumeGuard、SkillDistiller；固定 Provider vs 可插拔 Provider；有无 AgentTeams 共享状态。

裁判纪律

LLM-as-Judge 先通过金标准集校准，记录一致率与 κ；prompt 或模型变化需要重新校准，周抽样监测漂移。
